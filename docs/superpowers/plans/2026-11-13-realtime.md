# Real-time Updates Implementation Plan

Goal: automatically collect enabled email/calendar changes and update open pages.
Architecture: Redis Streams queues and workspace workers; SQLite transactional outbox;
Graph webhooks/renewal with polling recovery; SSE browser invalidation.
Tech stack: existing Python/FastAPI/SQLite/React plus redis-py and Redis >=7.
Spec: ../specs/2026-11-13-realtime-design.md

## Global constraints
- Preserve all existing reliability fixes and manual checks, tenant boundaries, Done states.
- Opt-in per account. No provider side effects in development. No auto-send/read marking.
- Queue hints and change topics contain no message bodies, tokens or credentials.
- Maintain Windows compatibility. Disabled Redis feature leaves ordinary startup working.
- Source/tests first, then one minor release and bundled frontend regeneration.

## Review focus
- Crash after commit/before publish: replay the transactional outbox.
- Duplicate/out-of-order callbacks: deduplicate or safely repeat idempotent collection.
- Redis/provider outages: bounded retry, visible degraded state, no lost acknowledged work.
- Workspace switch/logout: close SSE before delivering further data.
- Streaming load: finite separate capacity and slow-client timeout.
